# SinceVision 源码还原：从计划到内核与宿主集成

> 整理日期：2026-10-29。依据工作区已有计划、源码、差分证据与阶段报告整理；本文不代表重新执行了测试。报告和状态文件更新日期不同，数字只表示对应阶段的快照。

## 1. 背景与目标

SinceVision 是基于 Qt 的机器视觉软件，包含图像处理、定位测量、缺陷检测、点云与设备通信等插件。目标是从原始分发文件出发，识别模块边界和运行行为，逐步恢复可编译的内核及宿主，并用原版结果作为对照。最终愿景是可重复构建、无隐式原厂模块回退的宿主；这与已有局部内核通过验证是两个不同的验收层级。

初始盘点约 98 个自研模块，其中 `plugins` 下有 74 个流程工具插件；`.sv` 配方是 JSON 文本。早期将部分插件判断为 C++/CLI，随后通过 PE 检查修正：SV09/SV10 目标插件是原生 C++ x64，主要使用 Qt；ILSpy 适用于 C# 脚本桥等托管组件，原生内核则主要依靠 Ghidra 和汇编分析。第三方 Qt、OpenCV、HALCON、PCL 等作为依赖登记，不把它们当作自研源码还原。

## 2. 计划与推进路径

原计划按依赖分为 SV00–SV16：先建立 PE 清单、哈希和依赖边界，再分析配置格式、插件协议、流程引擎和 UI，随后覆盖采集、基础图像算子、测量、3D、通信和脚本，最后进行宿主差分、设备联调及发布审计。计划中明确区分内核、独立装具、桌面集成和真实设备验收，不能用某一层的通过替代全链路完成。

实际工作重点落在 SV09 定位/模板匹配/几何测量与 SV10 斑点/缺陷/3D。10 月 15 日续作计划将双目拼接、轮廓剖面、3D 平面以及 ROI 基础设施列为优先项，后续再处理圆测量、拟合、缺陷、点云和标定等模块。每项按原版入口定位、还原、差分、接入宿主、配方回归和证据登记推进；无法稳定复现的原版行为单独记录。

## 3. 实际方法

1. **建立边界**：盘点原始二进制及依赖，定位导出函数、插件调用链、参数和数据结构；用反编译结果寻找候选逻辑，再以汇编核对关键分支和运算顺序。
2. **恢复纯 C++ 内核**：按几何、卡尺、缺陷、模板、3D、拼接等领域归档源码；必要时显式调用同版本第三方运行时，例如模板匹配使用 HALCON。
3. **构造差分装具**：给原版和恢复实现输入相同数据，对比返回码、数值位模式、图像或文件；对可能挂起的原版调用使用子进程隔离。浮点差异用 ULP 和绝对误差说明，不把近似等价写成位级一致。
4. **接入 Qt 宿主**：通过节点封装参数、调用内核、显示图形与结果，并逐步引入统一的结果 JSON 和配方能力。宿主演示能够运行某个内核，并不自动证明原插件的全部编排和配置兼容。
5. **保留证据**：源码位于 `code/kernels/`，装具在 `code/harness/`，宿主在 `code/host/`，对照结果在 `code/evidence/`，计划与状态分别在 `rebuild/` 和 `code/metadata/`。

## 4. 主要成果

- **几何与卡尺**：还原点线关系、圆拟合、旋转矩形、采样及剖面卡尺等。宿主使用说明记录剖面卡尺 319,542,000 项检查、0 失败、maxULP=0；旋转矩形顶点的特定近零结果仍有最高 2048 ULP 差异，但绝对误差小于 1e-12，按语义等价记录。
- **模板匹配**：恢复创建和查找链并绑定 HALCON。阶段报告记录模型文件 63,602 字节逐字节一致、832 个轮廓坐标位级一致；查找的主要输出槽位一致，仿射矩阵仍有约 2–5 ULP 差异。排查中确认图像宽高、缩放条件与反编译器误判的栈槽复用会显著影响结果。
- **斑点与缺陷**：斑点沿用此前恢复成果并接入宿主，现有 smoke 证据返回成功、检测出两个候选；状态文件仍列出历史 18 组用例在宿主重放的缺口。高度过滤 200 例位级对照通过；焊缝缺陷随机差分记录为 39/40，存在末位不稳定案例。
- **3D 与点云**：完成平面拟合、迭代拟合、确定性 RANSAC 路径、体积和高度差等内核的对应测试。识别出 SImagePro 点结构为 `(y, x, z)`，HeightMeasure 点云头为 `{rows, cols, resX, resY}`；ROI 取点使用排序后的修剪均值和 `1e-5` 高度缩放。
- **拼接与标定**：报告记录双目拼接 200/200、点云合并 300/300；`getRigidTrans3D33` 1000 例、16000 项位级一致；PLY 读写及高度限幅变换 60 例通过，三维轴构建链 500 例通过。矩阵逆和带噪刚体变换仍有 ULP 残差，已经登记止损。
- **Qt 宿主**：已有模板匹配、几何测量、轮廓、拟合、3D、拼接和校正等演示入口；具体操作及阶段测试命令见 `code/host/USAGE-RECOVERED-KERNELS.md`。节点覆盖不等于全部原插件或原桌面工作流完成。

2026-10-12 状态报告的阶段统计为 71 个内核函数、其中 65 个位级验证、6 个近似完成、29 个差分装具；报告后续补入了 10 月 15–19 日的部分结果，因此这些总数不应当作当前全项目实时统计。

## 5. 关键经验与风险

逆向中数据布局、调用约定、浮点计算顺序和第三方库版本与算法公式同样重要。反编译伪代码可能误判复用的栈槽；要结合指令、输入输出探针和差分结果交叉验证。对可疑原版行为应保留观察和证据，例如垂直线分支的未初始化值、部分高度处理调用挂起，以及 `getRigidTrans3D33` 的退化输出；恢复实现是否忠实复现与生产使用是否安全需要分别判断。

现有成果主要证明指定样本和路径下的内核行为。`remaining-module-status.json`（2026-10-15 快照）仍列有插件编排、属性及结果字段映射、RANSAC 分支、配方保存重开、部分缺陷和点云 GUI 等缺口。设备采集、PLC、完整桌面交互及发布级来源审计属于更高层验收，现有资料不足以认定其全部完成。原始库可能挂起或包含未初始化行为，差分结果也不能推广为对所有输入的保证。

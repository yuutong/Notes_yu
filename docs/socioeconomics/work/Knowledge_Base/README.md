# 个人知识库工程

> 将长期积累的 Markdown 笔记整理为可维护、可检索、可追溯并可对话的个人知识系统。

## 项目结论

当前工作区已经从单纯的 Docsify 笔记站点，升级为由五层能力组成的个人知识库：

1. Markdown 继续作为唯一正文来源。
2. 内容治理工具统一格式、标题和重复内容。
3. 构建工具生成主题地图、质量报告、机器索引和关系图。
4. Docsify 与 Obsidian 分别承担发布阅读和本地编辑。
5. 本地聊天服务检索原文后生成带引用的回答。

这些能力彼此独立：即使聊天模型暂时不可用，原始笔记、主题导航和全文搜索仍然可以正常使用。

## 工作内容分类

### 内容治理

解决“同一主题多份正文、标题不统一、链接容易失效”的问题。

- [Markdown 笔记库的内容治理](knowledge-governance.md)
- 重点：单一权威页面、旧路径兼容、统一模板和隐私边界。

### 自动化质量工具链

把重复执行且容易遗漏的检查变成命令。

- [知识库自动化与质量工具链](automation-toolchain.md)
- 重点：格式、标题、去重、构建、审计和提交前检查。

### 智能问答

把“翻目录找笔记”变成“提问—检索—回答—核对来源”的过程。

- [本地 RAG 知识库聊天系统](rag-chat-system.md)
- 重点：中文检索、上下文构造、流式回答、引用和安全边界。

### 维护与发布

规定新内容如何进入知识库，以及哪些内容可以发布到公开网站。

- [知识库的日常维护与网站发布](maintenance-and-publishing.md)
- 重点：收件箱、复核、构建、审计、GitHub 发布和本地服务。

## 验收标准

一次知识库变更只有同时满足以下条件才算完成：

- 所有 Markdown 通过格式检查。
- 没有缺失标题、未闭合代码块和失效本地链接。
- 自动生成的知识库文件没有过期。
- 新笔记能从主题地图或导航进入。
- 聊天回答能够回到具体来源笔记核对。
- API Key、公司内部资料和个人隐私没有进入公开内容。

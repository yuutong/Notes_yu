# Markdown 笔记库的内容治理

> 内容治理的目标不是让目录看起来整齐，而是保证知识只有一个可信来源，并且能够被稳定引用。

## 问题背景

长期积累的笔记容易出现四类问题：

- 同一篇正文复制到多个主题目录，修改后版本逐渐分叉。
- 文件名、一级标题和页面标题不一致，搜索结果难以判断。
- 手工侧边栏与实际文件不同步，页面存在却无法进入。
- 旧链接在移动文件后失效，历史引用无法继续使用。

这些问题在普通浏览时只是“不方便”，进入 RAG 阶段后会直接降低回答质量：重复正文会被多次召回，冲突版本会让模型无法判断哪个结论可信。

## 核心原则

### 一个主题只有一个权威正文

通用计算机知识放在 `docs/computerScience/`，AI 目录只保留机器学习、模型训练、部署和具体 AI 项目。其他目录需要这些基础知识时使用链接，不再复制正文。

无法立即删除的旧路径改成兼容跳转页，并通过 `kb-canonical` 标记指向权威页面。这样既保留旧链接，也不会把跳转页当作独立知识参与去重和问答。

### 正文是唯一数据源

人工维护的内容只写在 Markdown 中。以下文件属于派生结果，可以随时重建：

- `KNOWLEDGE_BASE.md`：知识库总入口。
- `kb/topics/*.md`：按主题生成的知识地图。
- `kb/index.json`：搜索和 RAG 使用的机器索引。
- `kb/graph.json`：笔记节点与内部链接关系。
- `kb/quality-report.md`：孤立页面、失效链接和重复正文报告。

派生文件不应手工修补统计数据，应修改原文或构建脚本后重新生成。

### 新内容先进入收件箱

临时想法先写入 `inbox/`，避免为了快速记录而破坏正式目录结构。整理时依次判断：

1. 是否已有同主题权威笔记。
2. 应该合并、建立链接，还是新建页面。
3. 内容属于公开知识、个人隐私还是历史归档。
4. 是否具备结论、示例和来源，能够升级为长期笔记。

### 保持链接兼容

站点和 Obsidian 统一使用标准 Markdown 相对链接。移动或重命名文件后必须运行链接审计，不能仅依赖页面肉眼检查。

## 目录职责

- `docs/AI/`：机器学习、深度学习、训练与部署。
- `docs/computerScience/`：编程语言、系统、网络、图形学和视觉基础。
- `docs/math/`：数学与信号处理。
- `docs/Electronics/`：电子、通信和测量仪器。
- `docs/socioeconomics/`：工作实践、自我管理和公开方法总结。
- `inbox/`：尚未整理的草稿。
- `archive/`：已经失效但仍需保留的历史内容。
- `private/`：不允许发布的隐私或内部资料。

## 笔记成熟度

YAML 中的 `status` 表示内容状态：

- `draft`：临时记录，结论和来源可能不完整。
- `unreviewed`：已有正文，但尚未按当前标准复核。
- `evergreen`：可以长期引用的权威笔记。
- `archived`：只保留历史依据，不代表当前结论。
- `alias`：旧路径兼容页，不是独立正文。

## 内容模板

可复用知识笔记优先采用“结论—背景—原理—示例—常见错误—相关笔记与来源”的结构。工作日志可以更简洁，但至少保留日期、结论和依据。

## 常见错误

- 为了分类方便复制整篇正文，而不是建立链接。
- 直接编辑 `kb/` 中的生成文件，下一次构建时修改被覆盖。
- 将 API Key、密码或公司内部日志写进 Markdown。
- 一次性给所有旧笔记添加大量标签，造成标签体系失控。
- 移动文件后只检查当前页面，没有运行全库链接审计。

# VS Creator 1.6.2：从还原计划到阶段成果

> 整理日期：2026-10-29。依据本地计划、源码和验证报告整理，本文未重新运行测试。数字是对应报告中的阶段快照，不代表整套产品或全部输入均已验证。

## 背景与计划

VS Creator 是 KEYENCE VS 系列的 PC 配置与管理软件，涵盖桌面编辑器、网页画面、视觉模拟、AI 学习和设备交互。原始分发目录为 `C:\ty\Project\KEYENCE\KEYENCE\VS Creator 1.6.2`，恢复工程主要位于 `C:\ty\Project\KEYENCECode`。目标从识别可恢复的内容开始，逐步推进到可编译编辑器、独立视觉内核和原版行为对照；完整产品重建仍未完成。

2026-09-11 静态预检统计 226 个 PE 文件：165 个纯 IL、1 个混合程序集、60 个原生 PE；其中包括第三方与语言资源。50 个 source map 的 3,434 个 source 条目中有 3,433 个包含文本，按路径和内容去重为 3,154 对，仍混有第三方和生成代码。50 个按名称选取的 Keyence 程序集保留大量可读类型及成员名；三个 WPF 样本有 728 个 BAML 资源，未发现独立 PDB。

最初计划依次固化样本和哈希、提取前端文本、试验托管和 WPF 反编译、追踪业务流程，再调查混合模块、原生算法、Node 服务及模型，最后在隔离环境验证行为。源文本、反编译代码、可编译工程和行为一致是不同的验收层次。

## 源码提取与桌面重建

后续依据程序集静态引用、动态加载和 XAML 引用确定范围。项目记录使用 ILSpy 导出 111 个程序及依赖程序集、52 个语言资源程序集，产生 21,462 个 C# 文件和 1,442 个 XAML 文件；50 个 map 对应的 3,154 份不同源文本也被保存。163 个程序集导出进程均返回成功，并检查错误标记、XML 与引用路径；这不是语义或运行等价的证明。

原始导出保存在 `src`，修复后的工程在 `rebuild/src`。入口工程早期曾因 XAML 命名空间编译失败；经过代码、资源与依赖修复，项目 README 记录 60 个纯托管产品工程全量编译通过，连接页、主编辑器和基础离线流程实际运行。默认过渡部署仍依赖部分原版组件，源码桥接测试宿主与默认部署的依赖范围不同。

## 原生边界和传统视觉

ControllerDotNet 是托管与原生混合模块，托管声明不包含原生实现。工作先保存原生入口汇编，再重建 C++ 导出和 C# 客户端。项目报告记录 60 个 C++ 导出、71 项验证和 23,018 个检查案例；隔离测试的源码桥接宿主完成基础拍摄、仿真、编辑与保存重开，没有加载原版 ControllerDotNet，但仍使用原版 Simulator 的部分能力。

算法恢复以地址、调用链、数据布局为锚点，结合 Ghidra 伪代码、汇编、输入输出探针及原版指令对照，核实浮点顺序、定点舍入和结构布局。NCC 涉及模板、掩膜、金字塔、旋转、排序及判定；Intensity 涉及区域、灰度统计和结果服务；Area 涉及灰度计数与判定；Blob 已恢复连通域、洞填充和部分质心语义。

保存工程执行器可直接读取受支持的 Inspection.vsib、PTNP 和 BMP，独立执行已覆盖的 NCC、Intensity 和 Area 配置。项目总览记录五种多工具任务及五次重开共 209 个值一致；真实混合任务 22 次请求、74 个值和两张 BMP 一致。这些是具体场景的对照，不代表任意任务图。Blob 的角度、周长、圆度和完整宿主调度仍在推进。

## AI、学习服务与条码

AI 工作按 C# 应用层、C++ 数值核心和训练部署链分层，覆盖分类、检测、分割和 OCR，包括分类 SVM、检测标定与量化编排、OCR 增强和模板选择、共享整数神经网络算子。计划记录 OCR 小骨干 214 层及五个输出逐位一致；分割骨干 410 层执行，原版可捕获的 346 层逐位一致，其余 64 层在原版融合省略。结论限于指定模型和捕获数据。

OCR 训练入口记录有时间差：9 月探针受真实图对象及缓冲约定阻塞；后续 AI 计划记录 10 月 15 日原版指令路径已执行并返回，但完整训练流程及更多输入的对照仍列为待办。源码串联工作流的冒烟通过也不等于完整训练等价。

学习服务 pkg 分析提取明文 bootstrap 与载荷，识别 153 个应用模块路径和 283 个 npm 依赖名；业务主体为 V8 code cache，不能据此声称恢复了 JS 源码。报告指出 52 个 `saved_model.pb` 是加密载荷，模型分析依赖其他容器解码。

条码模块从 DspWinProcess 的表、校验字符串、共享内存协议和函数追踪入手，整理出 54 项码制表、1D 结果记录 0x1B0、2D 结果记录 0x7D8、参数默认值和四阶段管线。2D 步长由分配和拷贝处的静态证据交叉支持，部分字段仍为推断。Qt Demo 使用还原的管线与记录，但 QR 和 1D 解码数学为参考实现。报告记录自测 10/10；QR 误码纠错未完成，1D 仅支持合成图水平中线扫描，真实扫描、Simulator 调度和运行快照仍待验证。

## 边界与经验

工程还包含定位工具、机械手抓取等 C++/Qt 示例及分析记录。可运行或局部自测通过，并不代表所有原版数值和交互一致。传统视觉工具、通用宿主调度、Web/Node、设备集成和 AI 全模式仍有缺口，完整产品验收未完成。

实践中应将结论绑定到来源、地址、输入和验证方式：先用静态信息缩小范围，再以原版指令或产品结果对照，最后将已确认语义落成可编译代码。不同日期的计划和报告应结合对应证据阅读，避免将历史阻塞、后续进展和未完成验收混成同一状态。

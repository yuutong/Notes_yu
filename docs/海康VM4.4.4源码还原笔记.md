# 海康 VisionMaster 4.4.40 源码还原：从计划到阶段成果

> 整理于 2026-10-29，依据本机 `Applications\rebuild` 中的计划、分析及历史证据；本文没有重新执行测试。4.4.40 对应本次所称 VM 4.4.4。报告中的结果是对应日期的快照，功能演示不等于原厂算法已经完整还原。

## 背景与目标

工作从安装目录、帮助、SDK、配置及二进制出发，分为多相机深度图拼接和 AI 工具两条线。目标是识别模块和接口，恢复可编译的实现，逐步以相同输入与原版对照，最后接入宿主、验证工程保存重开及部署依赖。验收分为局部内核、独立程序、产品宿主和真实设备几个层次，不能以某一层的运行结果代替全链路完成。

安装包中的客户端是 .NET/WPF，模块界面有托管包装，服务端和算法模块主要是原生 C++；XML、帮助文档和 SDK 提供参数、模块关系与接口线索。托管部分用 ILSpy 分析，原生部分结合导入导出、字符串、反汇编和探针研究。第三方依赖及未恢复的原厂库需明确登记。

## 多相机拼接：计划与实施

2026-10-11 的 `PLAN-MULTICAM-STITCH.md` 先确认产品包含拼接标定、坐标变换和多数据源深度图拼接；帮助资料描述最多十个输入。计划 MS00–MS12 按盘点哈希、接口注册、托管反编译、数据结构、原生加载和服务协议、标定/变换/拼接内核、原版差分、宿主集成及部署审计推进。计划表是初始状态，后面追加的执行记录才反映同日的后续工作。

实际工作找到 SDK 测试深度图和产品示例，解析并列拼接 `.sol` 为 ZIP 容器，内含流程 XML、模块参数和附件。样本 `.raw` 是每像素 u16 深度与 u8 亮度交错，尾部带宽高、比例和偏移标签；早期诊断误按连续 u16 读取，造成有效像素判断错误，后续已修正。这是数据布局需要先于算法验证的具体教训。

自研 `OwnStitchRunner` 实现系统变换、重栅格化和最远/最近/均值融合，报告记录三幅官方样本校正后拼接为 15100×798，并完成恒等变换和重叠误差的自洽检查。随后 `StitchFlowDemo` 将配准、两路变换和融合串起来，WPF 的 `VmStitchStudio` 提供流程图、图像查看、参数、日志、来源图与重叠差异热力图。

初版配准只搜索 X 且受平坦背景影响，报告后来改为质心初估、二维局部搜索与像素精化。最后一轮记录 dx=-29、dy=-5，输出有效像素 1,908,448，重叠深度差中位数为 0，并检查了单源行和重叠行的保留情况。前一轮 6092×800、3,387,139 有效点的结果属于修正前记录，不能与最终结果混为同一次测试。

原版平台和 MVD 内核运行均被授权阻塞：平台初始化记录无加密狗或软件授权未激活，直连工厂返回 `0x80100015`。因此这些自研路径和自洽结果尚不能证明与原版逐像素一致；标定、融合方式、边界及真实多相机数据仍需取得合法授权后差分。原版运行器已有源码和编译产物，可作为复测起点。

## AI：接口、演示与验证

2026-10-15 的 `PLAN-AI-RESTORE.md` 涵盖分类、目标检测、OCR、实例分割。计划从 82 文件清单和哈希开始，依次研究接口、模块胶水、引擎协议、神经后端、界面和宿主；原版数值验证依赖算法许可。

分析得到五层调用链：`ModuleFrame` 模块框架 → `IMVS*Modu` 参数及流程胶水 → `MVDCNN*Cpp` SDK 包装 → `MVD_DLAlgorithm` 调度 → CPU/GPU 神经后端。L2 接口通过原始导入库的编译链接验证；L1 已整理虚表槽语义及 110 个参数键，L3 记录 21 个导出、调用协议和图像槽布局；L4 对 sigmoid、eltwise_add 记录了无许可门条件下的逐位对照，其他大量算子仍待恢复。这些是不同层级的成果，并非完整神经网络内核。

界面方面，四工具的 XML 参数树、控件、默认值和联动规则已提取为 Qt 规格，14 个托管程序集作为行为参考。独立分类、检测和 OCR 四页式 Qt 演示覆盖导入、标注、学习和测试；它们在无许可时使用明确标注的本地管线，不能视为原厂模型推理。计划中的四工具原版属性页/画布/结果表及产品宿主集成仍未完成。

历史自检记录分类 24/24、检测真值命中 13/16 且正常图误报 0/8、OCR 字符召回 64/64。10 月 16 日真实数据评估更能说明局限：分类 92/142（64.8%），PCB 检测命中 1/6 且正常图误报 6/6，车牌 OCR 为 76.2%；报告列出的参考管线分别为 81.0%、11/12 和 98.2%（OCR 为 LCS 指标）。这些结果受各自数据集、模型和指标约束，不能泛化为产品精度。报告分析分类特征表达不足、检测受板面背景变化影响、OCR 存在字符碎裂及形近字混淆。自建 `VMMD` 模型容器也不等同于原版模型格式。

原版 AI 工厂同样受 Virbox 算法许可阻塞，接口链接成功不等于实际模型推理验证。获取许可和相应模型后，应按同一输入记录原版与恢复实现的输出、环境及哈希；实例分割还需适用模型。

## 现状与后续

已有成果是拼接独立演示及样本自洽验证、AI 接口与分层分析、部分原语差分和三个本地 AI 演示；尚无证据证明完整 VM 源码、原版算法数值等价、产品宿主或设备链路已全部恢复。下一步应先在有效授权环境建立原版基线，再补齐拼接边界与真实采集数据、AI 模型推理和剩余算子，随后验证宿主编辑、保存、新进程重开与部署来源。

拼接计划曾记录调试时修改 `ServerAuthConfig.ini` 的授权类型及 `ServerConfiguration.ini` 的端口池；这是历史记录，当前配置是否仍为该值应单独核查，避免将其当成现状。

# VS Creator 2.0.14 源码还原：从计划到独立 AI 分割工具

> 整理日期：2026-10-29。依据工作区计划、源码说明与历史验证记录整理；本文没有重新运行实验。各数字是指定实验的结果，不代表整个产品或现场精度。

## 1. 目标与范围

本次工作的重点是还原 VS Creator 2.0.14 的 AI 分割高速模式：从原程序定位参数、训练和推理路径，恢复可独立运行的处理流程，再制作可学习、检测和验证的桌面工具。原模型权重及通用张量运行库明确作为依赖保留；独立工具不以调用原版 AIRemoteEngine、DLTrain 或嵌入原窗口代替自己的处理流程。

这不是整个 VS Creator 产品的源码完全恢复。分类、检测、OCR 等另有应用层和原生内核移植计划及阶段成果；本文主要记录资料最完整、已形成独立应用的 AI 分割。原工程格式、相机/PLC、设备部署以及所有原版算法的数值等效仍不在已完成范围内。

## 2. 从计划到交付

原计划先定位新版界面参数与原生分支，对比旧版 AIS 实现，再完成独立内核、模型持久化、命令行和桌面界面，最后做原版对照与端到端验收。完成标准包括高、普通感度训练和预测、模型保存重载、标注编辑、结果展示及可重复验证；不能仅凭界面运行来证明算法一致。

实际推进大致经历以下阶段：

1. **定位与拆解**：以 2.0.14.0 的 AIRemoteEngine 和 DLTrain 为证据基线，登记原文件散列，分析 UI 参数、原生函数、模型图和运行库边界。高速模式默认开启，改变后需要重新学习。
2. **恢复计算链**：实现高速缩放、分块、预处理、骨干特征、学习、推理及融合；再接入普通感度的 14 通道目标、邻域亲和和训练调度。模型图及其损失和优化器仍由保留的运行库执行。
3. **独立应用**：Python 内核接上 PyQt6，补齐数据集、标注、训练、验证、判定、报告、自动选图和参数比较。随后推进 C++ 原生内核和 Qt GUI，打通真实数据及模型生命周期。
4. **真实数据与迭代**：转换 0828 标注并试训，检查独立测试；开展 fber 两种标注格式的转换、训练和 GUI 验收；最后修正两张错误标注与 C++ 模型生命周期，并保留历史模型。

更广泛的四个 AI 应用计划将托管应用层、原生数值内核、训练部署链分开记录。其历史计划记录 AIS 骨干 410 个算子均可执行，346 个可捕获层与原版逐位一致；这属于该对照语料的骨干结果，不能外推为完整分割工具逐位一致。

## 3. 关键还原方法

先通过反编译定位候选函数和结构，再结合汇编、常量与原版直接调用核对；对同一输入比较几何、像素和模型输出，记录位级一致、浮点误差与未覆盖分支。将原版权重、通用运行库、独立源码和验证装具分别登记，避免混淆依赖与自主实现。

高速缩放比例与异常大小有关，并非固定缩小一半；分块在 256、320、384、448、512 等骨干尺寸中选择，使用重叠区权重融合。图像缩放使用原路径的定点插值规则，掩码前向散射以保留小标注。普通感度使用 NHW14 目标：标注、权重、膨胀区、邻域亲和及统计配置分别占用不同通道。分析时还纠正了一个重要误读：五段表是亲和强度，不是学习率；学习率另由异常大小映射。

训练、量化和推理必须保持模型所记录的特征运行时一致。builtin 与 XNNPACK 的量化特征不同，不能把两者混用或声称数值相同。独立工具的异常等级采用有效范围最大概率乘 100，属于明确标注的独立标度，不能直接假定等于原版等级或照搬原设备公差。

## 4. 形成的工具与验证

Python/PyQt6 工具支持图像及标注导入编辑、检测范围、学习与续训、模型保存重载、浮点和 INT8 检测、全集验证、统计及离线报告。数据集可共享图像而分别保存工具标注和学习状态；导入图像按源路径引用，迁移项目时必须同时保证原图路径可访问。自动选图和异常大小比较能够真实训练和验证，但采用独立策略，未证明与原版一致。

C++ 版本提供原生内核、JSONL 命令行和 Qt GUI，支持训练、取消、续训、预测、验证和量化；运行时无需 Python，但仍依赖模型资产、LiteRT、TensorFlow C API 等。其内核支持范围不等于 GUI 已提供全部编辑控件。

已有验证记录包括：

- 12 组几何规划与原版纯函数一致；39 项像素/数学核检查中，浮点插值最大误差约 5.96×10⁻⁸，部分项目并非逐位一致。合成训练、取消续训、新进程重载、大图分块及 INT8 导出均有对应记录。
- 普通感度示例完成 4 张图、6 轮、24 步训练，损失从约 0.9229 降至 0.4441，重载结果逐位一致。这验证流程，并非工业精度或原版端到端对照。
- C++ 对齐记录报告 0828 的 187 张、20 轮、14960 步训练损失和两份检查点与 Python 一致，新模型的 547 张整图推理对照通过。这是 C++ 与 Python 的对齐，不能替代与原产品的完整对照。
- fber 数据有 55 张图，YOLO 与 ANN 转换后的掩码一致；35 张训练一次，两工程共享模型，另独立推理。固定验证阈值后，10 张测试图中 7 张 NG 均检出、3 张 OK 均未误报，NG 平均 IoU 72.36%。样本很小且存在同背景、预标注等限制，不能据此推断现场零漏检。
- 2026-10-27 将 0828 的 741、742 两张恢复为原始 OK、空掩码；547 张标签、掩码和原图散列与冻结来源核对一致。模型生命周期修改后，记录显示 7 个生命周期场景、29 个 GUI 场景通过；单图推理与基线逐位一致。本轮没有重新完成全量训练或 547 图验证。历史独立测试 34 张 NG 中检出 31 张，不能写成全部检出。

## 5. 尚未完成与经验

尚缺原版各段内部轮次、数据增强、混合尺寸规划及缺陷统计影响分块的部分细节；也缺与原版完整 UI、硬件命令的端到端逐像素对照。原部署容器、工程保存格式和相机/PLC 协议尚未恢复。局部纯函数对照、独立流程闭环、C++ 与 Python 对齐，以及真实生产验收是不同层次，必须分别描述。

这次工作的主要经验是：模型之外的缩放、舍入、掩码、分块融合和运行时选择都可能影响结果；反编译结果需要用指令和实验交叉确认；数据标签、训练/验证隔离和模型状态与算法本身同样影响结论。每次实验应保留输入、配置、版本、散列、指标口径与失败案例，不能把小样本结果当作现场性能保证。
